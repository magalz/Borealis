# 0006 Set minSdk to 28

## Context and Problem Statement

Which minimum Android API level should Borealis support? Distribution data (Google Play, late 2025): API 26+ covers about 97-98% of phones, API 28+ about 94-95%, and API 29+ about 88-90%. TVs lag behind: Fire OS 7 (Fire TV) is Android 9 (API 28), and many Android TV sets and boxes from 2018-2020 stayed on Android 9. Handhelds (Retroid, AYN) are mostly Android 10 or newer.

## Decision Drivers

* Reach on Fire TV and Android TV devices, which lag on Android versions.
* Keeping the number of version-specific code branches low.

## Considered Options

* 28 (Android 9)
* 29 (Android 10)
* 26 (Android 8.0)
* 30 (Android 11)
* Earlier round: 21 as upstream
* Earlier round: 23

## Decision Outcome

Chosen option: "28 (Android 9)", because it keeps Fire TV (Fire OS 7) and Android TV 9 devices, and drops only Android 8.x (about 3% of phones). A few version branches remain.

Newer APIs remain usable at runtime behind `SDK_INT` checks; minSdk only trades branches for reach. compileSdk 37 and targetSdk 36 are inherited from 12.2. The upstream "root" flavor (maxSdk 25) is incompatible and is disabled.

### Consequences

* Good, because Fire TV (Fire OS 7) and Android TV 9 devices are kept.
* Good, because only Android 8.x is dropped.
* Bad, because a few version branches remain in the code.

## Pros and Cons of the Options

### 28 (Android 9)

* Good, because it keeps Fire TV (Fire OS 7) and Android TV 9.
* Good, because it drops only Android 8.x (about 3% of phones).
* Bad, because a few version branches remain.

### 29 (Android 10)

* Good, because it removes some branches (thermal status, `isHardwareAccelerated`, `MediaStore.Downloads`).
* Good, because it does not remove the runtime Vulkan check needed by PyroWave.
* Bad, because it excludes Fire OS 7 and many Android TV 9 devices (about 10-12% of phones).

### 26 (Android 8.0)

* Good, because it covers about 97-98% of phones.
* Bad, because it adds more branches and old-device testing, for only about 3% more coverage than 28.

### 30 (Android 11)

* Good, because `KEY_LOW_LATENCY` and `setFrameRate` need no branches.
* Bad, because it cuts a large share of TVs and some handhelds (Retroid Pocket 2+ runs Android 10).

### 21 as upstream (earlier round)

* Bad, because it is incompatible with current AndroidX and Compose, which require API 23 or higher.

### 23 (earlier round)

* Bad, because the gain over the chosen option is marginal.
